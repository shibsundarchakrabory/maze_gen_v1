How this maze generator works

Everything runs client-side in vanilla HTML, CSS and JavaScript — no libraries, no build step, no network requests. Open index.html and it just works.

The pipeline

  1. Model the grid. The maze is stored as a flat array of cells, each holding four boolean walls (top, right, bottom, left). Walls are always written to both neighbouring cells so the two sides of a boundary can never disagree.
  2. Generate. Each algorithm is a JavaScript generator that yields an event every time it carves or adds a wall, which lets the animation loop draw progress frame by frame without freezing the UI.
  3. Render. The renderer paints the whole maze on a square canvas in a single batched stroke, scaled for the device pixel ratio, and overlays the entrance, exit, active cell and solution path. Because the canvas is exactly 1:1 and holds nothing but the maze, Download PNG gives you a clean 1600 × 1600 image of the maze alone.
  4. Solve. A breadth-first search from the top-left cell to the bottom-right cell finds the shortest possible route, which is then revealed with a short animation.

The four algorithms

backtracker

Recursive Backtracker

A depth-first walk that carves as it goes and backtracks when stuck. Produces long, windy corridors with very few dead ends — the classic “textbook” maze.

prim

Prim's Algorithm

Starts from one seed cell and repeatedly connects a random frontier cell to the growing tree. The result has many short dead ends and a branching, organic structure.

kruskal

Kruskal's Algorithm

Collects every possible wall, shuffles them, then joins separate regions with a union-find structure. Paths end up evenly distributed across the whole maze.

division

Recursive Division

Works in reverse: the grid starts completely open and walls are added inward, leaving one random passage per wall. Expect long corridors and rectangular rooms.

Project structure

One concern per file: every style lives in its own file under css/, every piece of logic in its own file under js/, and any page other than the homepage sits in pages/. 

maze_gen_v1/
├── index.html          ← homepage (the generator)
├── css/
│   ├── base.css         ← design tokens, reset, typography
│   ├── layout.css       ← header, app grid, footer
│   ├── controls.css     ← panel, inputs, buttons, stats
│   ├── maze.css         ← canvas stage & status bar
│   └── pages.css        ← static content pages
├── js/
│   ├── config.js        ← constants, options, defaults
│   ├── maze.js          ← grid model + 4 generators
│   ├── solver.js        ← BFS shortest-path solver
│   ├── renderer.js      ← canvas drawing
│   ├── animation.js     ← frame-based animation loop
│   ├── controls.js      ← DOM wiring for the panel
│   └── main.js          ← bootstrap & orchestration
└── pages/
    └── about.html       ← this page
